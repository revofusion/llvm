All five files now pass their CIR prefix.

Summary of changes per file:

1. lambda.cpp
   - Added a regex capture to the A::foo() `cir.load deref` result so the SSA
     value is re-defined instead of re-using the prior `[[THIS]]` binding from
     an earlier function.
   - In the lambda operator() for A::bar(), the store of the incoming `this`
     argument was referencing the stale `[[THIS_ARG]]` from A::foo(); changed to
     `[[THIS_ARG2]]`, which is the capture already used for that function's
     argument.
   - Same `cir.load` result in A::bar() needed a fresh regex capture.

2. lambda-static-invoker.cpp
   - The static invoker's call to the lambda operator() was using exact SSA
     names `%2, %3`; replaced with captures `[[LAM_ALLOCA]]` and `[[REF_I]]`
     so the check is resilient to numbering drift.

3. coro-task.cpp
   - The `byRef()` `get_return_object()` call used the literal `%4` from an
     earlier coroutine; replaced with the already-captured `[[IntPromisseAddr]]`
     so it matches the current promise alloca in that function.

4. virtual-function-calls.cpp
   - The constructor `_ZN1AC2Ev` argument was hard-coded as `%arg0`, but the
     generated output uses `%arg1`. Replaced with a `[[ARG]]` capture and
     propagated it to the store of `this`.

5. variable-decomposition.cpp
   - The decomposition initializer is no longer emitted as a single
     `#cir.const_record` aggregate store; codegen now stores each field
     individually. Replaced the aggregate-constant check with field-wise
     `cir.get_member` / `cir.const` / `cir.store` checks while preserving the
     later member-load/add/store sequence.

No compiler source code was modified. Only the FileCheck comments in the five
named test files were touched.
